# 《Linear Single-Source Shortest Path, Almost》的 C 实现

论文：Iman Gholami, MohammadTaghi Hajiaghayi，arXiv:2611.34911v1（2026-11-25）。

本目录用 C11 实现论文的算法 9（`ShortestPaths`）及其全部中间构造，并用
"与 Dijkstra 对拍" 的方式验证实现是否忠实。

## 构建与运行

```bash
make                      # 需要 gcc
./sssp --n 400 --m 1200 --verify             # 默认：常数规模基例（扫描版 Dijkstra）
./sssp --n 400 --m 1200 --sep 2 --verify     # 走层级路径（缩放的分隔规模 b = L_N^2）
./sssp --type path --n 6 --maxw 4 --sep 2 --verify
./sssp --type grid --n 400 --sep 2 --verify
./sssp --bench                               # 一组基准
```

## 验证

`--verify` 与堆版 Dijkstra 对拍。在默认（不改 `--sep`）下，按论文的规模假设
N ≤ L_N^64，算法 9 落在"常数规模基例"，与 Dijkstra 逐顶点一致。

用 `--sep k` 把分隔规模缩到 b = L_N^k 后，层级路径会真正执行。此时本实现用
**状态图上的精确搜索**给出距离（`eval.c: state_graph_dist`），这一步验证的正是
§8.1 构造的核心结论：构造出的状态图与有序层级必须**以原长度实现每条物理测地线**
（引理 8.1、5.5、7.5）。测试结果（`--n 20..100`，多种种子，随机图与路径图）：

- 12/12 与 Dijkstra 完全一致（0 个不一致顶点）。

另外 `hier_validate` 会检查层级的不变量（子节点区间不重不漏铺满父区间）。

## 已知偏差（诚实说明）

1. **求值阶段**：算法 7/8 的槽扫描在 `eval.c` 中已实现（`--slot` 启用），但在部分实例上
   仍会漏发或发出偏大的值——槽/到期/补充候选值的交互尚未完全对齐论文的不变量。
   因此默认路径改为"在构造出的状态图上精确搜索"，它验证的是构造（§8.1），而不是
   求值过程。这是本实现与论文之间最主要的差距。
2. **§7.3 的宽度日历 / 局部搜索**未实现，J 直接由辅助图 Dijkstra 求出（同一对象，
   时间复杂度更高）。
3. **§5.4 的原子替换**未实现：层级用单元素叶子（定义 5.6 允许"剖分层级"的每部分是
   单元素），因此层级更高、时间界更松，但不影响任何正确性结论。
4. **§3.4/3.5 的 O(1) 结构**用 O(log n) 的倍增/段树替代。
5. 长度用 IEEE double 存储（模型上是"不透明寄存器"，只经 `len_*` 访问）。
